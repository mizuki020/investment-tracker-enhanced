# PROJECT_ROADMAP — 株式解析鑑定・自動化システム

更新日: 2026-11-06
状態: 設計方針（実装・実接続・自動売買の完了を意味しない）

## 1. 最終目標（North Star）

日々の株式取引の勝敗・機会損失・判断根拠を記録・検証し、再現性のある売買戦術を構築する。その戦術を、株価・ニュース等の取得 → 三知性体による解析鑑定 → 独立監査を含む四重防御 → 段階的な発注 → 約定・損益の検証 → 戦術改善、という安全なシステムへ発展させる。

**最終的な完全自動売買は長期目標であり、現段階では注文実行を許可しない。** まず分析精度、データ鮮度、再現性、リスク制御、監査証跡を証明する。

初期対象銘柄: 9983 ファーストリテイリング。複数銘柄化は後続段階。

## 2. 役割と保存先

- ChatGPT / 三知性体: 解析・合議・反証・行動トリガー・改善案。
- ラファエル: 相場構造、因果、期待値、整合性。
- リュミエル: 指標、短期変化、異常検知、第六感（単なる装飾的コメントにしない）。
- クラリタ: 企業・ニュース・材料の因果と持続性、リスク。
- Codex: コード開発、試験、障害解析、変更理由の記録。勝手に売買しない。
- GitHub: コード、テスト、設計・変更履歴、開発日誌。秘密情報やライセンス制約のある生データは保存しない。
- Obsidian: 正式人格、盟約、解析鑑定テンプレート、戦術原本、人間向け知識ノート。
- Google Sheets: 予測、仮想注文、実注文（将来）、約定、損益、機会損失、検証結果。
- J-Quants等: データ取得元。APIプランごとの遅延・権利制限を明示。
- 楽天証券の注文インターフェース: 将来検討。現段階では接続・注文しない。
- 独立監査エンジン: 将来の売買方向、銘柄、数量、価格、余力、重複、時間帯、異常値の検証。

## 5. 作業原則（Codexの全タスク共通）

1. 作業開始前に「North Star / 現在Phase / この作業の目的 / 完了条件 / リスク」を短く明示。
2. 根拠のない成功宣言をしない。実測・試験・推測を区別する。
3. 検証可能な小変更を優先。GitHubの `main` を明示承認なく変更しない。
4. APIキー・認証ヘッダー・口座情報・非公開の株価生データをログ、日誌、GitHubへ書かない。
5. 実売買・発注API・注文画面操作は明示的な別承認と安全審査が整うまで禁止。
6. データ取得時刻・対象期間・最終取引日・出典・制限事項を残す。
7. 変更時は関連テストを実行し、未実施のテストを「成功」と表現しない。
8. タスク終了時に結果、証拠（コミットSHA・テスト結果）、未解決問題、次の一手を日誌へ記録する。
9. この文書は方針書。Obsidianの正式テンプレート・人格・盟約を無断改変しない。
